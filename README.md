# Деплой на Beget (public_html фиксирован)

Этот репозиторий подготовлен к размещению на Beget, где **публичный корень всегда `/public_html`**. В проекте уже есть папка `public/` — именно её содержимое нужно загрузить в `/public_html`.

Важно: здесь описан **безопасный путь**. Секреты не храним в Git.

---

## 1) Что загрузить в `/public_html`

Откройте файловый менеджер Beget → папка `/public_html` и загрузите туда **содержимое папки `public/`** из репозитория:

- `index.html`
- `login.html`
- `register.html`
- `dashboard.html`
- папки `css/`, `js/`, `assets/`
- папка `api/`
- папки `lib/` и `db/` (они будут закрыты через .htaccess)
- файл `.htaccess`

> **Внимание:** загружается **содержимое `public/`**, а не сама папка `public`.

---

## 2) Файл `.htaccess` (защита)

В корне репозитория есть `.htaccess`. Он:

- запрещает листинг директорий;
- блокирует прямой доступ к `lib/` и `db/`;
- блокирует `config*.local*.php`, `.sql`, `.env*`.

**Обязательно загрузите этот файл в `/public_html/.htaccess`.**

---

## 3) Где хранить секреты (config.local.php)

Секреты **нельзя хранить в Git**. Для этого есть файл:

```
/public_html/api/config.local.php
```

Его нужно создать вручную на сервере, **на основе** файла:

```
public/api/config.example.php
```

### Пример содержимого (без секретов)

```php
return [
    'DB_HOST' => '127.0.0.1',
    'DB_PORT' => 3306,
    'DB_NAME' => 'horse_site',
    'DB_USER' => 'db_user',
    'DB_PASS' => 'db_pass',

    'APP_ORIGIN' => 'https://your-domain.ru',

    'TELEGRAM_BOT_TOKEN' => 'YOUR_BOT_TOKEN',
    'TELEGRAM_CHAT_ID' => 'YOUR_CHAT_ID',
];
```

**Почему нельзя держать секреты в Git:**
- репозиторий может попасть в чужие руки;
- токены Telegram и пароли БД можно украсть.

---

## 4) Импорт базы данных

Файл схемы находится в `db/schema.sql`. На Beget можно импортировать через phpMyAdmin:

1. Откройте phpMyAdmin в панели Beget.
2. Выберите свою базу.
3. Импортируйте файл `db/schema.sql`.

---

## 5) Проверка после загрузки

После деплоя проверьте:

- `/` открывается (главная)
- `/login.html` открывается
- `/register.html` открывается
- `/dashboard.html` открывается
- `/api/me.php` возвращает `401` если не залогинен

---

## 6) Пути в HTML/JS

Все пути к стилям/скриптам и fetch‑запросы настроены **от корня**:

- `/css/style.css`
- `/js/site.js`
- `/api/auth-login.php`

Это гарантирует, что всё будет работать из `/public_html`.

---

Если что-то не работает:
- проверьте, что `.htaccess` лежит в `/public_html`
- проверьте, что `config.local.php` создан вручную
- проверьте, что БД импортирована
